# Peilung — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Das Spiel „Peilung“ (`echo-locate`) als neuntes Rundenspiel: einen oder zwei Community-Sprüche im Nebel per Ping orten. Dazu bekommt das Rahmenwerk eine Schwierigkeit und eine Stufen-Leiter, deren Schritte Daten tragen.

**Architecture:** Das Rahmenwerk lernt zweierlei: `RoundContext.difficulty` (berechnet beim Materialisieren, im Labor aus dem Seed) und `GameType.step` mit `stagesScore`, gespeichert als `game.round_plays.steps`. Antworten werden bei jeder Antwort neu berechnet und nie gespeichert. Ein neues Modulith-Modul `echolocate` (reine Logik und Clip-Aufbereitung, kein Schema) liest den Audio-Pool über dessen ersten Export `AudioPoolQuery`. Der Adapter `EchoLocateGameType` in `game.internal` verdrahtet beides. Im Frontend kommt `games/echolocate/` dazu: reine Module (Typen, Sonar, Rauschen, Ablauf, Entwurf, Rangliste) unter einer Canvas-Komponente, die nur zeichnet.

**Tech Stack:** Kotlin 2.4 / Spring Boot 4.1 / Spring Modulith 2.1 · JUnit 5 + kotest-Matcher + mockk · Jackson 3 · `javax.sound.sampled` · PostgreSQL 18 (Flyway) · Vue 3 + TypeScript strict + Vitest + @vue/test-utils (happy-dom) · Web Audio · Tailwind v4.

**Spec:** [`docs/superpowers/specs/2026-10-25-peilung-design.md`](../specs/2026-10-25-peilung-design.md). Vor jedem Task lesen, der Plan argumentiert aus ihr. Referenz-UI ist der Spike, Stand `20db6a38` (Branch `feature/audio-snippet-game-mechanics-473e7c`): `webapp-vue/src/spike/listen/{field.ts,noise.ts,engine.ts,RadarField.vue}` und die Seite `webapp-vue/src/pages/c/[slug]/spike/radar.vue`. Lesen mit `git show 20db6a38:<Pfad>`; die Clips des Spikes sind nicht im Repo.

**Entscheidungen dieses Plans** (die Spec überlässt sie dem Bauenden oder schweigt):

1. **`game.internal` kennt nur `echolocate`, nicht den Pool.** Der Poolzugriff (`playable`, `prepared`) sitzt in `echolocate.EchoLocateClips`. So gilt die Spec-Zeile „`game → echolocate`, `echolocate → audiopool`“ wörtlich.
2. **`steps` hält genau einen Eintrag pro Stufe.** Ein Schritt ohne Eingabe (Anspielungs „mehr hören“, ebenso der falsche Tipp, der in Phase eins eine Stufe kostet) hängt JSON-`null` an. Damit gilt immer `steps.size == stage`, und die Antwort zu Stufe `i` ist `step(params, i, steps[i])`.
3. **JSON-`null` als Eingabe ist keine Eingabe.** Jackson liest `"input": null` als `NullNode`, nicht als Kotlin-`null`. `GameTypeHandle.step` macht daraus `null`, bevor ein Spiel es sieht.
4. **`guessActionFor` bekommt den Parameter `stagesScore: Boolean`, ohne Default.** Ein vergessener Aufrufer soll nicht kompilieren.
5. **`difficultyOf` liest den ersten Auftritt aus `history`**, nicht aus `previousParams`. Beim Materialisieren ist beides gleich (alle früheren Runden der Edition haben größere Nummern), und die Funktion braucht so nur eine Eingabe.
6. **Labor-Schwierigkeit:** `internal fun labDifficulty(seed: Int): Double = seed.mod(11) / 10.0` in `LabService.kt`. Kotlins `mod` ist nie negativ.
7. **Der Ablauf des Felds ist ein reines Modul** (`flow.ts`: Zustand + Tipp → neuer Zustand + Wirkung). Die Spec nennt es nicht, aber nur so ist ihre Liste der Feld-Tests ohne Canvas und Uhr prüfbar. `SonarField.vue` zeichnet, `EchoLocateBoard.vue` verbindet Ablauf, Ton und Server.
8. **Das Feld nutzt immer alle Pings, bevor es Pins nimmt.** So steht es im Ablauf der Spec (ohne Modus-Knöpfe, Clemens 2026-10-28). „Weniger zu benutzen ist erlaubt“ gilt für den Server: `judge` nimmt einen Tipp nach beliebig vielen Schritten.
9. **Clip-Aufbereitung in Gleitkomma,** mit der Rechnung des Spikes (`noise.ts`, `onset`): Fenster-Pegel `10·log10(mittleres Quadrat + 1e−18)`, Rauschboden = sortierte Pegel an Index `floor(n × 0.1)`. Ausgabe 16 Bit, gerundet und geklemmt; die Abtastrate bleibt die des Pools. Die Lautheit (RMS) gleicht der Browser an, wie im Spike.
10. **Zuordnung bei Gleichstand:** sind beide Summen gleich, gilt die Reihenfolge der Pins (`pinOf = [0, 1]`). Schritt-Antworten sind nach `delayMs` sortiert, bei Gleichstand stabil (erst Ziele, dann Störquellen).
11. **`MyPlayDto.steps` trägt `{input, answer}`, `GameEntry.steps` nur Eingaben.** Wo das Frontend `me` zu einem `GameEntry` macht (`RoundCard`, Laborseite), bildet es die Schritte auf `input` ab. TypeScript fängt das nicht: `StepView[]` passt auf `unknown[]`. Ein Test hält es fest.
12. **Bach und Kuh als MP3 mit `CREDITS.md`,** wie Blockierungs `sounds/` (Tabelle Datei · Aufnahme · Urheber · Lizenz). CC0, CC BY oder CC BY-NC (countdown ist nicht-kommerziell), Lizenz an der Quelle geprüft.

## Review Focus

Was die Spec impliziert, aber kein Task von sich aus testet. Jede Zeile ist einem Task als Test zugeordnet:

1. **`"input": null` im Skip-Body** (das Frontend lässt das Feld bei Anspielung weg, ein anderer Client schickt vielleicht `null`): Anspielung skippt wie heute, `steps` bekommt `null`. → Task 2, Task 3.
2. **Ein Ping, dessen Antwort nie ankam** (Netz weg nach dem Schreiben, 409, Neuladen): das Feld steht nicht für immer auf „Sonar lädt …“. Ohne neuen Schritt ist der Ping nicht verbraucht; mit neuem Schritt erscheint er ohne Welle. → Task 11 (`refused`, `synced`), Task 12 (Brett).
3. **Ein Doppeltipp auf einen Ping**: genau ein Request geht raus; zwei Requests mit demselben `fromStage` ergeben genau einen Schritt und einen 409. → Task 2 (Repository), Task 11 (Tipps während `loading`).
4. **Ein Clip, der zwischen Ziehen und Materialisieren aus dem Pool verschwindet:** die Runde spielt, an seiner Stelle schweigt sie, das Frontend wirft nicht. → Task 7 (Assets), Task 10 (`shotsOf` ohne Puffer), Task 13 (Spiel mit fehlendem Asset).
5. **Ein Clip ganz aus Stille oder kürzer als drei Fenster beziehungsweise als beide Blenden:** kein Einsatz, kein Schnitt, kein Absturz, keine Blende über das Ende hinaus. → Task 6.
